# AI-Powered Legal Document Analyzer — Stages 1–6

A B.Tech Computer Science capstone project that analyzes legal documents with
**Legal-BERT** (`nlpaueb/legal-bert-base-uncased`).

| Stage | What it adds | Status |
|-------|--------------|--------|
| 1 | Paste text → clauses, key information, potential risk indicators, summary, simple-English explanations | Done |
| 2 | Upload a **PDF** or an **image** → text extraction (PDF text layer, **OCR** for scans/photos) | Done |
| 3 | **Legal-BERT embeddings + FAISS semantic search** inside the analysed document | Done |
| 4 | **Ask Questions** about the document (retrieval; LLM answers optional) | Done |
| 5 | Key-sentence summary, optional LLM summary, transparent **risk score**, missing-clause and numeric checks | Done |
| 6 | Optional **read-aloud**: click Listen to hear text spoken | Done |

Not implemented yet: Stage 7 (Raspberry Pi camera / touchscreen). The Pi can already be used as a display (see below). Stage 4's answers are generated by an LLM only if you configure one; otherwise the app answers in retrieval-only mode.

## Project Overview

```
PDF / image upload ──► text extraction (PDF text layer or OCR) ─┐
Pasted text ────────────────────────────────────────────────────┤
                                                                ▼
                         PREPROCESSING (clean, sentences, passages)
                                          │
                                          ▼
                                     LEGAL-BERT
                      ┌───────────────────┼─────────────────────┐
                      ▼                   ▼                     ▼
            Clause detection     Key information        Potential risk
            (14 types)           extraction             indicators
                      └───────────────────┼─────────────────────┘
                                          ▼
                       Summary + Simple-English explanations
                                          │
   Legal-BERT passage embeddings ──► FAISS index ──► SEMANTIC SEARCH
                                          ▼
                                  React dashboard
```

**How Legal-BERT is used (honest description):** The pretrained checkpoint
has no classification head, so it cannot output labels such as "Payment" or
"High Risk". Legal-BERT encodes every passage of the document into a
768-dimensional vector, and these vectors power the Stage 3 semantic search.
Clause detection, key-information extraction and risk indicators use
transparent keyword and pattern matching, and every result shows its source
sentence. No accuracy numbers are claimed and the model has **not** been
fine-tuned on any dataset.

## Features
- Text editor with word / character / sentence counts
- **Stage 2:** drag-and-drop upload of PDF, PNG, JPG, TIFF, WEBP (max 15 MB, first 30 PDF pages). Text-layer PDFs are read directly; scanned pages and images use OCR. The extracted text appears in the editor for review before analysis.
- Preprocessing that preserves currency values, dates, percentages and section numbers; passage splitting so long documents are never truncated at 512 tokens
- 14 clause types, key information, LOW/MEDIUM/HIGH *potential* risk indicators with evidence, structured summary, simple-English explanations
- **Stage 3:** Semantic Search page: type a question in your own words (e.g. "how can the contract be ended") and get the closest passages, ranked by cosine similarity from a FAISS index
- **Stage 4:** *Ask Questions* page. Legal-BERT + FAISS retrieve the passages that match your question. With no LLM configured the app shows the closest sentence and passages (nothing is generated). With an LLM configured, the passages are sent to it with a strict "answer only from these passages" prompt and the answer cites them.
- **Stage 5:** key-sentence summary (real sentences picked with Legal-BERT embeddings, not repetitive); an optional LLM plain-English summary; a transparent 0-100 risk score with its formula, numeric checks (late-payment rate, short termination notice, long non-renewal window) and "potentially missing clause" checks; a closest-sentence suggestion per clause from Legal-BERT similarity (supplementary, never changes Detected / Not Detected)
- **Stage 6:** optional voice output. A **Listen** button next to answers and summaries reads the text aloud, only when clicked, using the browser's built-in voices. There is no voice input and nothing is spoken automatically
- Backend status badge, loading states, friendly error messages

## Technology Stack
**Frontend:** React, Vite, Tailwind CSS, Lucide icons
**Backend:** Python, FastAPI, Pydantic, Uvicorn
**NLP / AI:** Hugging Face Transformers, PyTorch, Legal-BERT, FAISS (faiss-cpu), PyMuPDF (PDF reading), RapidOCR (OCR, pure pip, no extra program to install)

## Backend Setup
Needs **Python 3.10 or 3.11** (64-bit) and internet on the first run.

```
cd AI_Legal_Document_Analyzer_Stage3
cd backend
python -m venv .venv
.\.venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
uvicorn main:app --reload
```
- Backend: **http://127.0.0.1:8000** · Swagger docs: **http://127.0.0.1:8000/docs**

> **First run:** Hugging Face downloads Legal-BERT automatically (a few hundred
> MB, cached afterwards). Wait for "Legal-BERT loaded and ready" in the terminal.
> The OCR engine starts the first time you upload an image or scanned PDF, so
> that first OCR takes a few extra seconds.

## Frontend Setup
Needs **Node.js 18+**. Use a second terminal.
```
cd AI_Legal_Document_Analyzer_Stage3
cd frontend
npm install
npm run dev
```
- Frontend: **http://localhost:5173**

## How to Run
Two terminals are required.

**Terminal 1 (backend):** `cd backend` → `.\.venv\Scripts\activate` → `uvicorn main:app --reload`
**Terminal 2 (frontend):** `cd frontend` → `npm run dev`
Open **http://localhost:5173**.

PyCharm: File → Open → select `AI_Legal_Document_Analyzer_Stage3`; then Settings → Project → Python Interpreter → Add Interpreter → Existing Environment → `backend/.venv/Scripts/python.exe`.

## How to Test

**In the app**
1. *Analyze Document* → paste `sample_documents/sample_service_agreement.txt` → *Analyze Document*. Explore Dashboard, Key Information, Clauses, Risk Analysis, Summary.
2. **Stage 2:** on the same page, upload a PDF (try printing the sample to PDF), or a phone photo of a printed page. The text appears in the editor with a note saying how it was read. Fix any OCR mistakes, then analyze.
3. **Stage 3:** open *Semantic Search* after analyzing and try "late payment penalty", "how can the contract be ended", "who owns the software". Results show the passage, its sentence range, and a cosine similarity.
4. Edit the text (change ₹250000 to ₹500000, delete the termination clause) and re-analyze; the results change, because nothing is hard-coded.

**Automated tests** (no internet; a small stand-in replaces only the Legal-BERT embedding step, everything else runs for real, including PDF reading, OCR and FAISS):
```
cd backend
.\.venv\Scripts\activate
pip install -r requirements-dev.txt
python -m pytest tests -q
```

## Raspberry Pi 3 as a client terminal (optional)
Legal-BERT is too heavy for the 1 GB Raspberry Pi 3, so the Pi only displays the dashboard; the laptop runs everything.
1. Put the laptop and Pi on the same Wi-Fi or phone hotspot. Run `ipconfig` on the laptop to find its IPv4 address (e.g. 192.168.1.20).
2. Laptop, backend folder: `uvicorn main:app --host 0.0.0.0 --reload`
3. Laptop, frontend folder: `npm run dev -- --host`
4. On the Pi, open Chromium at `http://192.168.1.20:5173` (use your IP).
5. If it does not load, allow ports 5173 and 8000 in Windows Firewall.

This setup has not been tested on a real Pi yet.

## Troubleshooting
- **"Could not reach the backend server":** Terminal 1 must be running `uvicorn main:app --reload` without errors.
- **Badge says "loading Legal-BERT..." for long:** normal on first run while the model downloads.
- **`pip install` fails on torch:** use 64-bit Python 3.10/3.11, or install the CPU build from https://pytorch.org first and re-run `pip install -r requirements.txt`.
- **`faiss-cpu` fails to install:** the app still works. It falls back to a NumPy search with identical results; the Semantic Search page shows "numpy-fallback".
- **"OCR engine is not installed":** run `pip install rapidocr-onnxruntime` inside the activated `.venv`.
- **Upload says "No text could be recognised":** use a sharper, well-lit, straight-on photo or a higher-resolution scan.
- **"This document is no longer indexed":** the server restarted or the document was replaced. Analyze the document again (indexes are kept in memory only).
- **Port in use / CORS error / PyCharm interpreter:** same fixes as before: change the port, run the frontend on port 5173, select `backend/.venv/Scripts/python.exe`.

## Connecting an LLM (optional, Stage 4 and 5)
Nothing is required: without an LLM the app works in retrieval-only mode. To enable generated answers, set environment variables **in the terminal where you start uvicorn** (Windows):

```
:: Option A - Claude API
set LLM_PROVIDER=anthropic
set ANTHROPIC_API_KEY=your-key-here
set ANTHROPIC_MODEL=claude-sonnet-5-5

:: Option B - local model through Ollama on your laptop (no key, offline)
set LLM_PROVIDER=openai
set OPENAI_BASE_URL=http://localhost:11434/v1
set OPENAI_MODEL=llama3.2
```
Then run `uvicorn main:app --reload` (add `--host 0.0.0.0` for the Pi). *Settings → Model and services* shows which LLM is active. Never put the key in the code or share it. With a hosted provider, passages of your document are sent to that service; do not use it for confidential documents unless that is acceptable. If the LLM call fails the app falls back to retrieval-only and says so. The Raspberry Pi 3 cannot run a local LLM; run Ollama on the laptop.

## Read aloud (Stage 6): what to expect
Text is spoken **only when you click a Listen button** (on answers and summaries). It uses the browser's built-in speech voices, so no audio is sent to this app's backend and it works offline.
- Works in most browsers. On the Raspberry Pi, Chromium needs a voice installed: `sudo apt install espeak-ng` (basic quality), plus a speaker or headphones.
- *Settings -> Read aloud* lets you choose the language and speed and test the voice.
- If a browser has no voices, the Listen button does not appear and the text is simply shown.

## Risk score: what it is
The 0-100 score is a point count (25 per HIGH, 12 per MEDIUM, 4 per LOW indicator, 8 per important clause type not found, capped at 100). It is shown with its formula. It is a reading aid, not a legal assessment, and has not been validated against expert judgement.

## Semantic search: what to expect
Legal-BERT was pretrained for language modelling, not for sentence similarity, so rankings are useful but imperfect and similarity values for different passages are often close together. The page therefore shows the full passage and a plain explanation of the score. Fine-tuning for retrieval, or a dedicated sentence-embedding model, is a natural next improvement.
